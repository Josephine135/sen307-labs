# Lab 4 Notes: Referential Integrity

In Part 4, deleting the "Library and Information Science" department failed with **Error 1451: Cannot delete or update a parent row: a foreign key constraint fails**. MySQL refuses because the `Student` table has a foreign key `dept_id` pointing to `Department`, and the student "Transfer Student" still referenced that department. Deleting the department would leave an orphaned student pointing at a row that no longer exists, so MySQL blocks it to protect referential integrity. I fixed it by first running an `UPDATE` to move the student to the Software Engineering department, after which the `DELETE` succeeded and the student was kept rather than lost. Another fix would have been to define the foreign key with `ON DELETE CASCADE`, which automatically deletes the dependent students (risky, because data is lost), or `ON DELETE SET NULL`, which keeps the students but clears their department (this needs `dept_id` to allow NULL). I could also have deleted the dependent student rows manually before deleting the department.
